# TrayGroups 托盘分组器（C++ 原生版）

1.5.1 修复设置窗口标题栏 X 和 Alt+F4 的关闭处理，关闭后丢弃未应用修改并释放窗口资源，托盘程序继续运行；“恢复全部图标”同时同步设置页的折叠开关。首次点击“打开保存目录”会先创建目标目录。设置页全部 13 个可见按钮/复选框、T 面板的 3 个按钮、详情/规则管理子窗口和五个页面的关闭入口均纳入本地交互回归。

托盘只显示一个 T。左键打开系统 ListView 分组图标面板：各组按顺序展开，只显示已经隐藏的分组图标；未分组图标继续由 Windows 管理。支持原程序左键、双击、右键操作，以及系统滚动条、方向键、Home/End、Page Up/Down。Enter 执行所选图标的左键操作，菜单键或 Shift+F10 执行右键操作，Esc 关闭。

1.5.0 使用 Win32 系统控件重新实现界面。分组面板由 ListView 和 ImageList 负责排列、选中效果、滚动和提示；字体、组标题、按钮、边框和颜色遵循 Windows 系统主题。默认宽度 420 逻辑像素、图标 28 逻辑像素、每行 4 个、显示名称和底部截图区。保留原有图标身份、分组、隐藏恢复及截图调度，不嵌入浏览器。

程序旁 `groups.ini` 的 `[Panel]` 可设置 `Width`、`IconSize`、`Columns`、`ShowNames`、`ShowCapture`；这些选项也可以在设置的“外观”页修改。尺寸随 DPI 缩放。`[GroupOrder]` 按文件顺序写入 `1=效率工具`、`2=影音娱乐`、`3=连接服务`，只排序真实分组，未列出的分组接在后面。手工编辑后从 T 菜单重新加载。

旧版自绘面板的 `Radius`、`Accent`、`LabelSize`、`Spacing` 不再生效；旧的 `[GroupLabelSizes]`、`[GroupLabelWidths]`、`[GroupLabelHeights]` 数据仍保留，系统组标题统一采用系统排版。

## 设置界面

设置窗口采用标准 `PropertySheet` 属性页，由系统管理标签页和“确定 / 取消 / 应用”。所有编辑先保存在草稿中；应用写入配置，确定应用并关闭，取消或关闭放弃尚未应用的修改。窗口位置单独保存。

- 分组：图标列表、组名、分组范围、图标详情和失效规则。
- 外观：面板宽度、图标尺寸、每行数量、名称与截图区开关。
- 截图：保存目录、文件名格式、间隔、当前状态、立即截图和打开目录。默认 10 分钟，保留既有截图配置，按每天零点对齐。
- 高级：身份识别方式、原图标折叠开关、恢复全部图标和资源占用。
- 关于：版本与便携配置说明。

参考 [AltSnap 的 PropertySheet 创建方式](https://github.com/RamonUnch/AltSnap/blob/e35ef154354260beea85cace25fede4f2758f0b7/config.c#L114) 和 [资源页布局](https://github.com/RamonUnch/AltSnap/blob/e35ef154354260beea85cace25fede4f2758f0b7/window.rc#L65)，使用自行编写的页面和业务逻辑。资源布局在 `resources/TrayGroups.rc`，可以用 ResEdit 或 Visual Studio 资源编辑器修改。HTML 外观试验保留在 `test/ui-preview/`，不参与程序运行。

内存目标：按任务管理器常见的专用工作集口径，每进程低于 **7 MiB**。本地 UI 回归覆盖设置窗口、100 个图标的面板及关闭释放，截图测试另测编码过程；不通过强制清空工作集降低显示值。实际占用受系统、缩放和图标数量影响，可从 T 菜单查看。

## 设置分组

1. 在列表中按图标和提示选中项目，Ctrl 可以多选。横向滚动可查看完整路径和易读的图标名称，例如“系统音量”“蓝牙设备”“网络状态”。
2. 输入或选择组名。默认范围是“仅选中的图标”，不会自动修改所有同名程序。
3. 点击“应用”。取消分组时选中项目，点“取消所选分组”，再保存。

选中图标后点“图标详情”，可查看真实 GUID（或未取得原因）、当前匹配键、运行时身份、匹配结果和隐藏状态。详情显示当前已生效配置，可选中复制文本；它不会猜测某次系统拒绝的具体原因，操作错误可查看本地日志。

“失效规则”列出当前未匹配、重复匹配、待确认及未启用识别方式的规则，说明路径不存在、编号/GUID/类别变化或程序可能未启动。选中旧规则，再选择当前图标并点“重新绑定”，会保留组名并替换原规则；也可删除所选规则或刷新列表。目标图标变化、匹配不唯一或已有目标规则时拒绝覆盖。路径和程序名规则保持原来的整体作用范围。该窗口点“确定”仅暂存，返回设置后仍需点“应用”；取消或关闭设置会放弃未应用修改。编辑使用独立副本，后台刷新不提前使用暂存规则。

“此完整路径的全部图标”会同时分组该路径的所有图标；“此程序名的全部图标”会修改所有同名程序。这两种范围需要明确选择，保存后清除所选范围内更具体的旧规则。

## 图标识别

默认 `IconMatch=path-guid`，单图标键为 `path-guid|完整程序路径|真实GUID`。GUID 由 Explorer 通知注册信息直接读取，不再按程序名、系统路径或窗口类别维护音量、蓝牙、安全中心等专用 GUID 表。同一程序的多个 GUID 图标分别识别；GUID 不随提示文字、数字 ID 或窗口变化而改变时，分组也不变。

普通注册图标可能没有 GUID，这时使用 `path-class-id|完整路径|稳定窗口类别|数字ID`，不虚构 GUID。窗口类别中的进程随机地址会通用地去除或解析为所属 DLL 名。GUID 也由程序自己选择，有些软件每次启动重新生成，不能保证所有软件都跨重启稳定。

高级页仍可明确选择路径＋类别＋ID、路径＋ID、路径＋类别＋提示等命名方式。只有当前所选方式生成的键参与单图标匹配，不再自动遍历旧命名规则或旧键别名。切换方式后原有单图标规则可能需要重新分组；完整路径和程序名的整组范围仍可使用。

实际操作同时核对当前进程 ID、进程创建时间、窗口、图标编号、程序路径、回调与真实 GUID。冲突、历史条目、无法确认的地址保持原状。名称直接显示原程序提供的提示文字，缺少提示时显示程序名，不维护系统图标名称表。

读取采用本机验证的内部 `ITrayNotify8` 接口，不增加其他 Windows 版本的接口回退。同步取得快照后立即注销，不增加固定等待或自建常驻线程。隐藏后的图标不在新快照中，因此隐藏前必须保存地址。隐藏/恢复使用 `Shell_NotifyIcon(NIM_MODIFY)`；有 GUID 时用 `NIF_GUID`，普通注册使用窗口＋编号。操作后扫描真实工具栏状态，不以接口返回成功或矩形仍存在作为隐藏依据。

默认启用 FoldOriginalIcons=1。需暂停时在“高级”页取消折叠开关，或使用“恢复全部图标”按钮；T 面板、设置窗口底部及右键菜单均有入口。这里的“全部”指本程序改为隐藏的全部图标，包含只剩磁盘记录的图标；不会批量显示你原本隐藏的图标。恢复同时暂停折叠，避免下一轮刷新又隐藏回去。仅有组名并不代表已隐藏；T 只列出 Explorer 确认隐藏的已分组图标。设置列表的“匹配状态”同时标明已隐藏、仍显示在 Windows 或折叠已暂停。

程序收到操作后自行显示托盘图标时，会在短时复查及后续刷新中再次折叠；复用同一恢复记录，不会重复记录。退出仍会恢复原图标。

原程序图标优先复制原托盘图标，取不到时使用该程序文件图标。T 图标同时嵌入 EXE 和设置窗口，不使用通用程序图标。

## 面板与窗口位置

“外观”页可以调整面板宽度、图标大小、每行数量和显示开关。组标题与图标文字遵循系统字体，不再单独设置每组字号和标签宽高。

设置窗口记住上次屏幕位置；屏幕布局改变后会调整回可见区域。关闭窗口只保存位置，尚未应用的分组修改会丢弃。

## 本地配置

同目录 groups.ini 为 UTF-8。启动自动读取；右键 T → “重新加载配置并刷新”可手动更新。“编辑 groups.ini 配置文件”可直接打开。

~~~ini
[Settings]
FoldOriginalIcons=1
IconMatch=path-class-id
DefaultGroupLabelSize=12

[Programs]
; 显式规则：同名程序的全部图标
; Everything.exe=工具

[Paths]
; 显式规则：此完整路径的全部图标
; C:\Tools\app.exe=工具

[Icons]
; 路径、窗口类别及 ID；以实际列表标识为准
; path-class-id|c:\windows\explorer.exe|atl@sndvolsso.dll|100=音量
; 单图标留空值表示取消分组，覆盖上面的整体规则

[Panel]
Width=420
IconSize=28
Columns=4
ShowNames=1
ShowCapture=1

[GroupOrder]
1=效率工具
2=影音娱乐
3=连接服务

[Window]
Left=100
Top=100
~~~

单图标规则优先于路径规则，路径规则优先于程序名规则；旧版“路径|ID”配置仍兼容。界面保存使用临时文件后原子替换。组名不宜包含 INI 保留字符（等号、换行）。

## 资源、恢复与编译

右键 T → 资源占用，显示任务管理器常见内存列的专用工作集，以及提交内存、总工作集。当前目标为每进程专用工作集小于 7 MiB，不强制清空工作集；打开界面和截图编码时的实际占用由本地回归和资源面板检查。

正常退出先合并内存与磁盘记录，恢复后逐项复查；等待截图结束时也会停止折叠。Windows 10 Explorer 托盘布局为非公开实现，系统升级可能影响兼容。

恢复记录保存在程序旁的 `restore-icons.ini`，与分组配置分开。每次隐藏前先写临时文件、调用 `FlushFileBuffers`，再原子替换正式文件；写入失败则不隐藏。Version=3 记录包含真实 `Guid`（普通注册为空）、原进程启动时间、窗口、图标编号、程序路径、窗口类别及 `WasHidden` 原始状态。程序原本已隐藏的图标不纳入新的隐藏操作。恢复失败的记录始终保留；只有核验可见或确认原进程已退出后，才清理相应记录。文件损坏时保留文件并停止新的隐藏，避免覆盖证据。

首次隐藏前，同一个 EXE 会启动一个低优先级的恢复看护进程，无额外托盘图标。看护只等待主进程结束；主进程崩溃或被单独强制结束时，它读取 INI 恢复本程序的隐藏操作，然后退出。正常退出时也会结束看护。若同时结束整个进程树，则靠下次启动或 `TrayGroups.exe --restore` 读取记录恢复。

强制关机、断电时进程无法执行恢复代码。已落盘的记录会保留；之后恢复时必须匹配原进程生命周期，原进程已退出的记录会被丢弃，不把旧记录套到重启后的新图标上。系统重启后图标由对应程序重新向新的 Explorer 注册。恢复文件无法重建已经退出的软件图标，也无法判断没有记录的历史隐藏图标是谁隐藏的。

旧版未保存 GUID，且被隐藏的图标无法从新快照补取 GUID。升级到 1.2.0 前先在旧版恢复全部并正常退出，等待主程序和看护都结束，再替换 EXE；保留 `groups.ini`、`config.json` 和尚未清理的 `restore-icons.ini`。不要在仍有隐藏图标时删除恢复文件，也不要手动更改其中的进程身份字段。

参数：`--settings` 打开设置；`--reload` 重载配置；`--stop` 正常退出并恢复；`--restore` 从 INI 恢复并暂停折叠（已有实例时通知它恢复，不退出）；`--background` 后台启动。内部 `--recovery-watch` 模式仅供看护使用。

源码统一放在 `src/`，窗口资源放在 `resources/`；根目录保留构建入口、说明和便携配置。目录按职责组织：

| 文件 | 职责 |
| --- | --- |
| `src/app/` | 主窗口消息调度、启动退出、版本号；`AppLifecycle.h` 集中管理运行/退出/销毁状态 |
| `src/config/TrayConfig.h` / `.cpp` | 独立配置对象及 INI 读写，窗口位置和暂停开关采用局部合并 |
| `src/tray/TrayIdentity.h` / `.cpp` | 独立身份与分组匹配模块，显式接收配置和本次运行的确认状态 |
| `src/tray/TrayGuid.h` / `.cpp` | 独立 COM 快照与真实 GUID/普通注册地址核验，无图标专用表 |
| `src/tray/TrayTypes.h` | 图标信息、进程生命周期和恢复记录的数据类型 |
| `src/tray/TrayDiagnostics.h` / `.cpp` | 图标详情文本、失效规则诊断及重新绑定校验 |
| `src/tray/TrayEnumeration.h` | Explorer 托盘扫描；每轮独立的进程与窗口类别缓存 |
| `src/tray/TrayRecovery.h` | 恢复 INI、记录合并、异常退出看护及旧记录迁移 |
| `src/ui/` | 系统 ListView T 面板、原生设置页、控件编号 |
| `src/ui/TrayInspector.h` / `.cpp` | 图标详情与失效规则对话框，独立编辑副本 |
| `src/capture/CaptureTimer.h` | 截图模块供主程序调用的公共接口声明 |
| `src/capture/ScreenCaptureTimer.cpp` | 独立编译的截图调度、编码和设置实现 |
| `src/common/` | UTF-8/文件工具、资源采样和本地日志 |
| `resources/` | 图标、系统主题清单、原生对话框及 EXE 版本资源 |
| `defaults/` | 发布用的干净默认配置 |
| `test/` / `test/build/` | 测试源码与诊断工具 / 编译产物、临时配置、报告、备份 |

`.h` 声明可调用的接口和数据类型，`.cpp` 实现具体行为。例如主程序通过 `CaptureTimer.h` 使用截图模块，无需了解 PNG 编码。配置、身份匹配和截图实现独立编译；配置对象不包含运行时身份，匹配器也不读取主窗口全局变量。

托盘扫描、恢复和界面头文件目前仍是主窗口私有实现，由主程序按依赖顺序包含；尚未全部改成独立编译模块。隔离的窗口集成测试仍包含宿主实现以注入模拟截图，独立配置/身份测试只链接对应模块。中文注释说明模块边界、图标句柄所有权、身份核验、日志落盘顺序及退出约束；`.clang-format` 统一源码排版。

`src/common/NativeHandles.h` 提供小型 RAII 封装。进程/文件句柄、远程读取缓冲区和截图 GDI 资源按作用域自动释放。托盘图标按值复制时调用 `CopyIcon`，移动时转移所有权，容器销毁时自动释放，避免裸 `HICON` 浅拷贝；系统借用图标先复制再持有。

`resources/TrayGroups.manifest` 启用系统控件主题，使用当前用户权限运行。`build.ps1` 依赖 MinGW g++、windres，以 `-Os -s` 构建发布版，输出 `test/build/TrayGroups.exe`。运行 `test/run-all.ps1` 顺序验证独立模块、截图集成、图标身份、隐藏与恢复、原左右键、设置页和截图编码；测试不会点击其他程序的图标。

1.1.2 将后台状态扫描与界面图片加载分开：后台刷新、隐藏/恢复核对和点击转发不复制图标图片，打开弹窗或设置时才加载。扫描缓存仅在当轮有效，避免跨轮复用 PID。资源面板复用一次内存/CPU 采样，线程数量改为每 5 秒统计。在本机隔离的 24 图标工具栏上连续扫描 20 次，加载图片约 99.5 ms，只读状态约 7.7 ms；这仅反映该扫描步骤，不代表整个程序或截图速度。


## 图标控制与权限

显示/隐藏使用原图标的注册地址，默认无需以管理员身份运行。没有取得可信注册信息或操作被系统拒绝时，设置列表提示保持原状；不再回退直接隐藏工具栏按钮。左键、双击和右键仍沿用原程序的回调消息与协议，GUID 不替代点击协议。

滚动内容不重建或移动弹窗；显示时将整个面板限制在当前屏幕工作区内。

## 定时截图

定时截图已整合进 TrayGroups，同一进程共用唯一的 `T` 托盘图标。左键 `T` 的面板直接显示下次截图时间、最近结果，并提供“立即截图”“截图设置”按钮。右键 `T` →“定时截图”也可立即截图、暂停、设置保存目录、文件名和间隔、查看截图资源占用或打开截图目录。默认每 10 分钟将所有显示器按物理布局合成一张 PNG，按日期建目录保存。截图在后台线程写入，不阻塞托盘操作；退出时会等待当前图片完成。截图只写入本地，不上传、不自动删除。

截图设置保存在 exe 旁 `config.json`，旧版 `ScreenCaptureTimer/config.json` 会在首次启动时迁移。默认输出目录为 exe 旁 `Captures`。便携目录需要有写入权限。

截图设置中的“截图间隔”支持 1–1440 分钟，在 `config.json` 中保存为数字字段 `IntervalMinutes`，旧配置缺省为 10。按当地当天零点对齐：15 分钟为 00、15、30、45 分；90 分钟为 00:00、01:30、03:00……。间隔不整除一天（例如 7 分钟）时，末段在次日零点结束并重新对齐。保存后立即重新计算下次时间；锁屏和休眠错过的时点不补拍。

运行 `build.ps1` 构建 TrayGroups 单一程序。截图源码在 `src/capture/`，截图测试在 `test/capture/`，所有新编译产物写入 `test/build/`。运行 `test/run-all.ps1` 执行全部测试。

运行 `.\package.ps1 -Version v1.5.1` 生成 `.\TrayGroups-v1.5.1-windows-x64.zip`。便携包包含 `TrayGroups.exe`、干净的默认 `groups.ini` 和 README；模板位于 `defaults/groups.ini`，不包含个人分组或恢复记录。`config.json` 首次启动时生成。升级时保留自己已有的配置和恢复文件。打包脚本检查文件是否齐全，并校验版本标签与 EXE 版本一致。

每次推送到 `main` 都会通过 GitHub Actions 自动构建、测试并打包，在对应运行页面的 Artifacts 中提供 Windows 便携包；也支持在 Actions 页面手动运行。推送 `v*` 标签时会额外自动创建 Release 并上传便携包。Release 需要仓库允许 Actions 的 `GITHUB_TOKEN` 写入内容。

发布约定：每次完成 bug 修复或新增功能，都必须递增版本号、验证后提交，并为该提交创建及推送 `v版本号` 标签，触发自动构建和 Release。bug 修复递增补丁版本（例如 `v1.1.2`），新增功能递增次版本（例如 `v1.5.1`）；修改 `src/app/AppVersion.h` 中的数字与文本版本即可同步 EXE 资源、启动日志和托盘提示。标签发布后不覆盖或复用，后续修复使用新版本。仅推送 `main` 不算完成上述发布流程。

每次版本发布前，必须在本地 Windows 上以发布模式运行 `.\build.ps1`，再运行 `.\package.ps1 -Version v版本号`，生成 `.\TrayGroups-v版本号-windows-x64.zip`，方便本地自测，直接在项目根目录查找。ZIP 必须包含对应版本的 `TrayGroups.exe`、默认 `groups.ini` 和 README；生成后校验包内容与 EXE 版本，并在发布说明中给出本地 ZIP 路径。更新版本号或包内文件后，重新生成本地 ZIP。

例如本次版本：提交后执行 `git tag -a v1.5.1 -m "TrayGroups v1.5.1"`，再执行 `git push origin main v1.5.1`，最后确认 Actions 成功且 Release 的便携包可下载。

## 本地调试日志

默认在 exe 旁记录 `TrayGroups.debug.log`，包含版本与实际运行路径、T 点击回调、登记状态、面板/菜单打开、截图排队、完成和 Win32 错误码。日志不记录截图像素。单文件达到约 1 MiB 时轮换为 `.log.1`，保留一份历史日志。右键 T 可打开日志或切换记录；也可在 `groups.ini` 的 `[Settings]` 下设置 `DebugLogging=0` 关闭记录。
