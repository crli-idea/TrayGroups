# TrayGroups 托盘分组器（C++ 原生版）

托盘只显示一个 T。左键 T 打开分组窗口：上方是分组列表，下方只显示所选组中已隐藏的原程序图标；图标支持原有左键、双击和右键操作。图标较多时可在下方翻页。右键 T 打开设置、配置重载、资源和退出菜单。双击 TrayGroups.exe 也可打开设置。T 不提供“未分组”入口，未分组图标继续由 Windows 托盘管理。首次打开 T 自动选中一个分组。

## 设置界面

设置使用 Windows Common Controls v6 系统主题，统一雅黑字体、紧凑间距、分组框和底部按钮。图标列表优先显示分组与隐藏状态，完整路径位于右侧。设置采用原生 Win32 分页对话框，分为“分组、外观、高级”。底部“应用”统一保存，“关闭”或 Esc 放弃未应用的修改（窗口位置仍记住）。支持 Tab 键切换控件。

- 分组：图标列表、组名、分组范围、取消所选分组。
- 外观：独立选择组名，设置字号、宽度、高度，不改变所选图标的分组。切换组名会暂存上一组的修改，统一应用后写入配置。
- 高级：图标识别方式与原图标折叠开关。

参考 [AltDrag 官方配置界面源码](https://github.com/stefansundin/altdrag/tree/e2740d605b0336a3b391fec26794718864b19521/config) 的原生分页、资源布局和按功能组织控件方式。这里使用自行编写的资源布局和设置逻辑，未复制其 GPL 代码；保留本程序的统一应用行为。参考资料保存在 test/reference/altdrag。

## 设置分组

1. 在列表中按图标和提示选中项目，Ctrl 可以多选。横向滚动可查看完整路径和易读的图标名称，例如“系统音量”“蓝牙设备”“网络状态”。
2. 输入或选择组名。默认范围是“仅选中的图标”，不会自动修改所有同名程序。
3. 点击“应用”。取消分组时选中项目，点“取消所选分组”，再保存。

“此完整路径的全部图标”会同时分组该路径的所有图标；“此程序名的全部图标”会修改所有同名程序。这两种范围需要明确选择，保存后清除所选范围内更具体的旧规则。

## 图标识别

默认 `IconMatch=path-class-id`。每个托盘图标以规范化的完整程序路径、稳定窗口类别和数字图标 ID 组成持久键，不使用 PID、窗口句柄或列表顺序。Explorer 中系统音量和蓝牙图标虽然路径相同，但窗口类别和 ID 不同，因此会得到不同的键；音量提示文字变化也不会改变身份。ATL 类名中的随机地址会解析为所属 DLL 名，例如网络 `pnidui.dll`、音量 `sndvolsso.dll`；无法解析时会去掉随机地址。

`path-guid` 仍可用于已能取得真实 GUID 的图标；缺少 GUID 时回退到 `path-class-id`。`path-id` 和 `path-class-tip` 也继续兼容。GUID 另用于 Windows 托盘隐藏/恢复接口寻址，不作为默认分组键。多个同路径图标即使文件名相同，也会由窗口类别和 ID 区分；无法唯一确认的规则会保持图标可见并显示“待确认”。

另外可选 path-id（路径＋ID）或 path-class-tip（路径＋窗口类别＋完整提示文字）。提示文字随音量、歌曲、网速变化时会失配，因此不作为默认。识别方式用于新建规则，已有规则仍可读取。单图标规则无法区分多个当前图标，或多条规则互相冲突时，显示“待确认”，保持原图标可见；此时不会继续套用路径或程序名规则。曾发生冲突的规则需要重新选择图标并保存确认。软件升级改变路径、类别或 ID 时可能需要重新分组。

实际操作另行核对运行中的程序 ID、进程启动时间、图标所属窗口和图标编号，避免把保存的规则当成运行时唯一身份。单图标规则在本次运行中绑定的窗口或程序生命周期变化后，需要重新确认。完整路径和类别规则用于启动时恢复分组，不能保证跨重启永久唯一；Windows 托盘枚举接口没有为所有软件提供统一的永久唯一标识。

折叠通过 Windows 托盘图标状态接口更新，使 Explorer 同时维护可见状态和布局。系统图标或其他软件拒绝更新时，保留原图标；不会退回直接隐藏工具栏按钮。恢复时重新查找同一运行中的图标并检查可见状态。恢复失败会保留 restore-icons.tsv，并暂停普通退出；下次仍可尝试恢复。旧版直接隐藏按钮的恢复仅用于兼容旧恢复记录。

本次按需求启用 FoldOriginalIcons=1。需暂停时在“高级”页取消折叠开关，或右键 T 选择“恢复全部原图标并暂停折叠”。当前本机验证 Edge 与 TrafficMonitor 的托盘图标已隐藏；Windows 安全中心现已通过 GUID 寻址成功隐藏，并出现在 T 的隐藏组。仅有组名并不代表已隐藏；T 只列出 Explorer 确认隐藏的已分组图标。设置列表的“匹配状态”同时标明已隐藏、仍显示在 Windows 或折叠已暂停。

程序收到操作后自行显示托盘图标时，会在短时复查及后续刷新中再次折叠；复用同一恢复记录，不会重复记录。退出仍会恢复原图标。

原程序图标优先复制原托盘图标，取不到时使用该程序文件图标。T 图标同时嵌入 EXE 和设置窗口，不使用通用程序图标。

## 分组标签大小

在“外观”页的组名框中选择或输入组名，设置该组的标签字号、宽度、高度，再点“应用”。无需选择程序。每组独立保存：

- 字号：8–32 磅。
- 宽度：120–600 逻辑像素，按所在屏幕 DPI 缩放。
- 高度：32–160 逻辑像素，0 为自动。为避免裁掉文字，实际高度至少能容纳字号。

设置窗口记住上次屏幕位置；屏幕布局改变后会调整回可见区域。关闭窗口只保存位置，尚未保存的分组修改会丢弃。

## 本地配置

同目录 groups.ini 为 UTF-8。启动自动读取；右键 T → “重新加载配置并刷新”可手动更新。“编辑 groups.ini 配置文件”可直接打开。

~~~ini
[Settings]
FoldOriginalIcons=1
IconMatch=path-class-id
DefaultGroupLabelSize=12

[Programs]
; 显式规则：同名程序的全部图标
; Everything.exe=工具

[Paths]
; 显式规则：此完整路径的全部图标
; C:\Tools\app.exe=工具

[Icons]
; 路径、窗口类别及 ID；以实际列表标识为准
; path-class-id|c:\windows\explorer.exe|atl@sndvolsso.dll|100=音量
; 单图标留空值表示取消分组，覆盖上面的整体规则

[GroupLabelSizes]
工具=12

[GroupLabelWidths]
工具=280

[GroupLabelHeights]
工具=0

[Window]
Left=100
Top=100
~~~

单图标规则优先于路径规则，路径规则优先于程序名规则；旧版“路径|ID”配置仍兼容。界面保存使用临时文件后原子替换。组名不宜包含 INI 保留字符（等号、换行）。

## 资源、恢复与编译

右键 T → 资源占用，显示任务管理器常见内存列的专用工作集，以及提交内存、总工作集。目标为每个程序的专用工作集小于 3 MiB；不强制清空工作集。分页 UI 在 100% 和 150% 缩放下，包含隐藏与鼠标转发流程后，设置窗口打开时采样约 2.1 MiB，测试结束时约 1.95 MiB；实际使用会变化。

正常退出先恢复并复查原图标。强制结束后，下次启动或 --restore 根据 restore-icons.tsv 尝试恢复。高权限程序可能拒绝转发，可选择“恢复全部原图标并暂停折叠”。Windows 10 Explorer 托盘布局为非公开实现，系统升级可能影响兼容。

参数：--settings 打开设置；--reload 重载配置；--stop 正常退出并恢复；--restore 恢复；--background 后台启动。

主逻辑在 TrayGroups.cpp；设置逻辑独立到 TraySettings.h，控件编号集中在 TraySettingsIds.h；资源采样在 NativeResources.h。TrayGroups.manifest 启用系统控件主题，使用当前用户权限运行，不强制提权。图标与原生对话框资源为 TrayGroups.ico、TrayGroups.rc。设置控件不再通过主文件中的逐项 CreateWindow 创建，重复的组名列表填充与组合框读取已合并。build.ps1 依赖 MinGW g++、windres，产物全部放 test\\build。测试源码、工具、临时配置、测试图片、报告和备份统一放 test；正式程序不包含测试入口。运行 test\\run.ps1 验证配置、图标身份、单 T 入口、标签大小、窗口位置、原左右键及恢复操作，以及 100% / 当前系统缩放下的分页布局、中文输入、键盘导航、应用/取消与打开设置时的内存。测试不会点击其他程序的图标。

Windows 托盘隐藏/恢复接口对部分系统图标需要真实 GUID；这是运行时寻址用途，与默认 `path-class-id` 分组键分开。分组切换及翻页保留当前弹窗左上角位置，只在超出屏幕工作区时调整，避免跟随点击位置逐次漂移。
## 定时截图子项目

定时截图已整合进 TrayGroups，同一进程共用唯一的 `T` 托盘图标。左键 `T` 的面板直接显示下次截图时间、最近结果，并提供“立即截图”“截图设置”按钮。右键 `T` →“定时截图”也可立即截图、暂停、设置保存目录和文件名、查看截图资源占用或打开截图目录。启用后每逢 10 分钟整点将所有显示器按物理布局合成一张 PNG，按日期建目录保存。截图在后台线程写入，不阻塞托盘操作；退出时会等待当前图片完成。截图只写入本地，不上传、不自动删除。

截图设置保存在 exe 旁 `config.json`，旧版 `ScreenCaptureTimer/config.json` 会在首次启动时迁移。默认输出目录为 exe 旁 `Captures`。便携目录需要有写入权限。

运行 `build.ps1` 构建 TrayGroups 单一程序。截图编码和测试代码保留在 `ScreenCaptureTimer/` 子目录。运行 `test/run-all.ps1` 执行两套测试。

每次推送到 `main` 都会通过 GitHub Actions 自动构建、测试并打包，在对应运行页面的 Artifacts 中提供 Windows 便携包；也支持在 Actions 页面手动运行。推送 `v*` 标签时会额外自动创建 Release 并上传便携包。Release 需要仓库允许 Actions 的 `GITHUB_TOKEN` 写入内容。

发布约定：每次完成 bug 修复或新增功能，都必须递增版本号、验证后提交，并为该提交创建及推送 `v版本号` 标签，触发自动构建和 Release。bug 修复递增补丁版本（例如 `v1.1.1`），新增功能递增次版本（例如 `v1.2.0`）；EXE 版本资源、启动日志和托盘提示中的版本号须同步。标签发布后不覆盖或复用，后续修复使用新版本。仅推送 `main` 不算完成上述发布流程。

例如本次版本：提交后执行 `git tag -a v1.1.1 -m "TrayGroups v1.1.1"`，再执行 `git push origin main v1.1.1`，最后确认 Actions 成功且 Release 的便携包可下载。

## 本地调试日志

默认在 exe 旁记录 `TrayGroups.debug.log`，包含版本与实际运行路径、T 点击回调、登记状态、面板/菜单打开、截图排队、完成和 Win32 错误码。日志不记录截图像素。单文件达到约 1 MiB 时轮换为 `.log.1`，保留一份历史日志。右键 T 可打开日志或切换记录；也可在 `groups.ini` 的 `[Settings]` 下设置 `DebugLogging=0` 关闭记录。

1.1.1 修复了托盘图标仍在 Explorer 中、但内部登记缓存丢失时左右键被忽略的问题。固定 T 入口不再依赖该缓存接受点击，重新登记遇到已有图标时会尝试更新它。这里的缓存是进程内存数据，不是 Windows 注册表。独立复现、回归测试和诊断工具位于 `test`，均不修改其他程序的托盘图标。

本次还统一了截图线程和主窗口的完成通知，避免截图结束后状态一直显示忙碌。截图线程使用低于普通级别的 CPU 优先级，托盘界面维持普通优先级，减少截图编码与前台程序争用 CPU；这不代表截图耗时会缩短，也不能保证消除所有系统卡顿。弹窗分页为截图控制区预留高度，状态只在面板打开时每秒更新。集成版截图统一使用上述有大小限制的调试日志，省去重复写入 `activity.log`。
