# 托盘 GUID 通用读取实验

分支：`research/tray-guid-discovery`。本目录只编译独立实验，不修改正式程序、不参与发布。

## 运行

需要 Windows x64、Explorer 和 MinGW-w64 C++17。脚本优先使用本机 MinGW，其他环境从 PATH 查找 `g++.exe`。

```powershell
# 只读当前 Explorer 的通知快照
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\test\guid-research\run.ps1

# 创建自己的测试图标，验证 GUID、隐藏、恢复、清理与错误匹配拒绝
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\test\guid-research\run.ps1 -SelfTest
```

源码使用 `-Os` 优化构建并保留研究用调试符号。产物和报告保存在忽略目录 `test/build/guid-research/`。默认只读报告含本机程序路径，勿直接提交；自测报告只记录检查及计数。脚本对测试进程设 15 秒超时，只终止测试进程。

`TrayNotifySnapshot.h/.cpp` 封装读取和严格匹配；`guid-probe.cpp` 是独立测试入口；`ToolbarState.h` 只读核对工具栏隐藏状态。修改状态的 API 只允许操作本次自测自己注册的 GUID。正常返回时删除测试图标，不调用 COM 偏好设置方法。

## 本机验证结果

2026-11-17：Windows 10 Home x64，Explorer 文件版本 `10.0.19041.4522`，优化构建自测 **19 项通过，0 项失败**。

| 检查 | 实测结果 |
| --- | --- |
| 真实 GUID 读取 | 通过 Explorer 内部 COM 快照取得，不按程序名或系统图标类型查表 |
| 同进程、同窗口的多个图标 | 两个每次随机生成的 GUID 均被准确读取并区分 |
| 普通 HWND + 编号注册 | GUID 为零；不会凭空生成“真实 GUID” |
| 错误匹配 | 拒绝无窗口的历史记录、错误路径、冲突 GUID、过期进程身份 |
| 路径规范化 | 通用展开 Known Folder GUID 路径，不特判 Explorer |
| 按取得的 GUID 隐藏/恢复 | 成功，工具栏的真实隐藏状态符合预期 |
| 隐藏后重新取快照 | 刚隐藏的图标、初始隐藏的图标均不能被重新取得 |
| 隐藏后调用 GetRect | 仍可成功返回矩形，不能作为隐藏成功与否的判断依据 |
| 自测结束 | 测试图标删除，旧窗口/旧快照不再命中 |
| 现有用户图标 | 8 个活动快照身份和偏好保持一致；工具栏扫描中所有现有图标的隐藏状态保持一致 |

多次快照耗时约 125–172 ms，包含主动等待 80 ms 的消息泵；不是纯接口性能数据。实验没有测正式程序长期资源占用。

## 读取方法与边界

使用 Explorer 的 `ITrayNotify8` 回调取得通知项，复制路径、窗口、编号、GUID 和偏好，再注销回调。COM 类及接口的固定标识属于接口协议，**没有写死任何具体图标的 GUID**。当前仅实现本机验证过的接口，不含未经验证的 Windows 7 回退。

这是未公开的内部接口；结构体和 vtable 布局只在当前系统验证。接口类型保留外部链接：放进匿名命名空间会让 GCC 在优化构建中按本地实现去虚化，实验曾因此异常退出；修正后优化构建通过。后续不能把本机结果当作所有 Windows 版本的兼容保证。

回调包含已退出程序的历史条目，不能按路径直接操作。实验匹配同时检查非空活动 HWND、图标编号、真实进程路径、PID、进程创建时间和 GUID 是否存在冲突；无法验证时拒绝。消息回调数据只在调用期间有效，因此复制字符串，不释放借用的 HICON。

这些核验不能证明一个窗口下的图标从未被删除再注册；相同进程/窗口/编号可能重新注册另一个 GUID，同一程序也可能每次启动生成新 GUID。研究快照只适合短期关联，不能作为永久存活证明。COM 的 preference 是 Windows 的显示偏好，不等于 `NIS_HIDDEN`。

## 正式接入前需要完成

1. 对有稳定非零 GUID 的图标优先用 GUID 匹配；普通图标保留现有路径/窗口类别/编号等规则。GUID 能标识注册图标，不意味着所有图标都具有跨重启稳定 GUID。
2. **隐藏前先持久化已取得的 GUID、运行时身份与原始隐藏状态**；写入失败则不隐藏。当前正式恢复文件尚未保存完整 GUID，不能只替换查询函数。
3. 正常退出、恢复看护、独立恢复、升级路径都需要消费同一份记录，先核验当前注册身份，再恢复本程序改变过的图标。原先隐藏的图标保持原状；过期或含糊记录不强行操作。
4. 首次接入时已被隐藏、且没有 GUID 恢复记录的图标，不能指望新 COM 快照补出它的 GUID。需设计迁移过程并验证，不能静默删除现有恢复能力。
5. 将内部接口探测失败与进程崩溃隔离；评估按需快照/缓存失效策略，避免每轮扫描都增加消息泵等待。保留现有点击消息转发，GUID 本身不提供左键、右键、双击协议。

本实验说明通用读取有可行路径，尚未完成上述正式接入及恢复迁移。
